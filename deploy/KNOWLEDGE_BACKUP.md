# Полная копия базы знаний: сервер ↔ Windows

Цель: после восстановления отвечать по сохранённым документам без повторного импорта, OCR, разбиения или построения embeddings.

## Что сохраняется

По умолчанию создаётся **обычная копия (`standard`)**. Архив `.akb.tar` содержит:

- SQL-дамп **всех таблиц базы приложения**: документы, фрагменты, embeddings, ручную разметку, FAQ, товары, настройки, пользователей, историю миграций и диалогов.
- Полный uploads: оригиналы PDF/Markdown, вложения, изображения, настройки виджета и другие сохранённые файлы.
- Холодную копию тома Weaviate с сохранением версии образа и имени исходного узла.
- Список моделей Ollama с точными digest, **без файлов весов**.
- Идентификаторы Docker-образов MySQL, Weaviate, Ollama и приложения и доступные immutable registry digest, **без самих образов**.
- RAG-конфигурацию, системный промпт, разрешённый список параметров моделей, счётчики данных и контрольные суммы.

Режим **`full`** дополнительно включает том Ollama и все четыре Docker-образа для автономного восстановления без загрузки моделей/образов из сети. Старые полные архивы формата 1 также поддерживаются. Размер обычного архива зависит от документов, SQL и векторного индекса: он тоже может составлять несколько ГБ, но веса моделей и образы не увеличивают каждую регулярную копию.

При обычном восстановлении уже установленный точный образ используется без скачивания. Если его нет, сценарий пробует получить его по сохранённому immutable registry digest и сверяет image ID. **Локально собранный образ приложения без публикации в registry скачать невозможно**: сохраняйте его на сервере, опубликуйте в доступном registry либо держите отдельную полную копию. Подмена произвольным latest не выполняется.

Кэш моделей при наличии копируется **локально на сервере** в новый том; исходный кэш монтируется только для чтения. Недостающие/отличающиеся модели скачиваются в этот новый том, затем проверяются digest. Если тег теперь указывает на другие веса или локальную модель нельзя скачать, восстановление останавливается до переключения. В таком случае нужна точная исходная модель либо полная копия. Совпадения названия или размерности вектора недостаточно. Перестроение сохранённых embeddings автоматически не выполняется.

Исходный `.env` и полное окружение контейнеров **не экспортируются**. Настройки внешнего адреса, разрешённых сайтов и интеграций берутся с целевого сервера. Для новой изолированной БД генерируются отдельные случайные пароли; JWT целевого сервера сохраняется либо генерируется при его отсутствии. Рабочая конфигурация восстановленной копии хранится приватно в `.knowledge-backups/restore-.../compose.json`, а не внутри переносимого архива.

Архив содержит конфиденциальные документы, хеши паролей пользователей и настройки БД, которые могут включать ключи внешних провайдеров. Он **не зашифрован**; храните его на защищённом диске/в зашифрованном хранилище. Восстанавливайте только собственные доверенные архивы: контрольная сумма обнаруживает повреждение, но не удостоверяет отправителя SQL и Docker-образов.

## Требования и влияние на сайт

- На сервере: Ubuntu/Linux, Python 3.10+, Docker Engine с Compose v2. Пользователь SSH должен иметь доступ к Docker и папке проекта. Сценарии не устанавливают пакеты и не повышают привилегии.
- На Windows: PowerShell и команды `ssh`/`scp` из OpenSSH. SSH alias позволяет настроить нестандартный порт и ключ. Проверка ключа сервера не отключается.
- Используйте один административный аккаунт для операций: ему должны быть доступны `.knowledge-backups` и `.knowledge-active.json`. Если они созданы другим аккаунтом через sudo, сначала администратор должен настроить доступ. Скрипты не меняют владельца чужих каталогов автоматически.
- Код этих сценариев должен быть опубликован и получен на обоих компьютерах. Команды ниже — примеры с заменяемыми `user@server` и `/opt/assist`.
- Поддерживается текущая **одноузловая Compose-схема** с локальными MySQL/Weaviate/Ollama. Для кластера, удалённых БД, API-key Weaviate и нестандартных хранилищ нужен отдельный адаптер. Платформа Docker при восстановлении должна совпадать: например Linux/amd64 → Linux/amd64.
- Резервная копия требует окна обслуживания: приложение и Weaviate останавливаются для согласованного копирования. В обычном режиме Ollama остаётся запущенным, его файлы не читаются для архива. В полном режиме образы сохраняются заранее, а Ollama также останавливается для копирования моделей. MySQL остаётся запущенным для транзакционного дампа InnoDB. Внешние cron/скрипты и другие писатели должны быть приостановлены отдельно. При обычной ошибке/INT/TERM выполняется возобновление сервисов; после аварийного выключения или SIGKILL проверьте их вручную.
- Модели и образы могут занимать десятки ГБ. В обычном архиве их нет, но на целевом сервере нужен диск для образов и отдельного кэша моделей, временных файлов и восстановленных данных, а также RAM для параллельного запуска двух ассистентов. При недостатке ресурсов проверка копии может не пройти. Ничего автоматически не удаляется.
- Обновление приложения и операции резервного копирования/восстановления используют общий lock. Не изменяйте контейнеры вручную параллельно этим операциям.

Создавайте копию после завершения импорта/обработки документов. Архив сохраняет текущее состояние, но не может завершить прерванную фоновую задачу за вас. Неизвлечённый текст и уже отсутствовавшие оригиналы восстановлением не создаются.

## 1. Скачать полностью рабочую базу знаний на Windows

Из локальной папки проекта:

Если Windows блокирует запуск `.ps1`, можно запускать выбранный сценарий отдельным процессом: `powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\Backup-Knowledge.ps1 ...`. Это не меняет постоянную политику системы. Для остальных сценариев используется такой же способ запуска с их именем и параметрами.

```powershell
.\scripts\Backup-Knowledge.ps1 `
  -Server user@server `
  -RemoteProject /opt/assist `
  -LocalDirectory D:\AssistBackups
```

Без дополнительных параметров создаётся `standard`: моделей и Docker-образов в архиве нет. Для редкой автономной копии добавьте `-Mode full`; для явного выбора обычной — `-Mode standard`.

Сценарий создаёт копию на сервере, возобновляет приложение, скачивает архив и `.sha256`, проверяет SHA-256. Незавершённая загрузка остаётся `.partial`, готовой копией не объявляется. Серверная копия также остаётся в `.knowledge-backups/transfers/`. Данные не передаются через PowerShell stdout: используется бинарный SCP.

Альтернатива непосредственно на сервере из папки проекта:

```bash
python3 scripts/knowledge_backup.py backup --output /home/user/assist-backups/knowledge-2026-11-09.akb.tar
# Автономная копия с моделями и образами:
python3 scripts/knowledge_backup.py backup --mode full --output /home/user/assist-backups/knowledge-full-2026-11-09.akb.tar
```

Существующая копия не перезаписывается. Не используйте имя предыдущего архива.

## 2. Загрузить архив и проверить восстановление

Выберите известный **фактический вопрос по документу** и короткий ожидаемый фрагмент ответа — например точное обозначение изделия или значение характеристики. Избегайте приветствия, общего вопроса или вопроса, на который возвращается только список документов.

```powershell
.\scripts\Restore-Knowledge.ps1 `
  -Server user@server `
  -RemoteProject /opt/assist `
  -Archive D:\AssistBackups\knowledge-ВАША-КОПИЯ.akb.tar `
  -Question 'ВАШ ПРОВЕРЕННЫЙ ВОПРОС ПО ДОКУМЕНТУ' `
  -ExpectedAnswer 'ОЖИДАЕМЫЙ ФРАГМЕНТ ОТВЕТА'
```

Происходит следующее:

1. Архив передаётся по SSH/SCP и сверяется по SHA-256.
2. Проверяется его состав и хеш каждого payload; опасные пути, ссылки, devices и лишние файлы отклоняются до создания хранилищ.
3. Используются точные локальные образы либо скачиваются образы по сохранённому registry digest; для полной копии загружаются образы из архива. Создаются **новые уникальные тома и отдельная сеть**; существующие тома не очищаются и не используются для импорта.
4. SQL импортируется в новый MySQL, файлы и индексы — в новые тома. Сверяются все исходные SQL-счётчики, затем запускается сохранённое приложение и штатные миграции на копии. Изменение числа документов/фрагментов/разметки/FAQ при запуске не допускается.
5. Проверяются SHA-256 каждого исходного файла uploads и классы/количество объектов Weaviate. В обычном режиме модели берутся из локальной копии кэша либо скачиваются; в полном — из архива. Для каждой сохранённой модели нужен исходный digest. Дополнительные модели в локальном кэше обычного восстановления допустимы. Затем проверяется работоспособность embeddings-модели с прежней размерностью.
6. Выполняется реальный запрос через API виджета, включая согласие при его включении. Требуются ожидаемый текст **и источники документов**. Одна такая проверка не доказывает правильность всех ответов; дополнительно проверьте несколько привычных запросов.

При ошибке поднятая копия останавливается, рабочее приложение не переключается. Файлы/новые тома остаются для диагностики; исходные данные не восстанавливаются поверх рабочей базы.

При успехе выводится `Restore directory: /opt/assist/.knowledge-backups/restore-...`. Копия доступна **только на loopback** сервера, по умолчанию порт 3210. Для просмотра с Windows используйте SSH-туннель:

```powershell
ssh -L 3210:127.0.0.1:3210 user@server
```

Затем откройте `http://127.0.0.1:3210`. Вход — пользователем из сохранённой базы. Проверьте несколько документов, их источники и ответы. Публичные ссылки/разрешённые сайты всё ещё используют настройки целевого сервера; для изолированного просмотра они могут требовать отдельной настройки. До переключения не принимайте реальные изменения пользователей в проверочной копии. Автосинхронизация на копии отключена.

## 3. Переключить рабочее приложение на проверенную копию

Только после успешной проверки:

```powershell
.\scripts\Switch-Knowledge.ps1 `
  -Server user@server `
  -RemoteProject /opt/assist `
  -RestoreDirectory /opt/assist/.knowledge-backups/restore-ВАШ-ID
```

Контрольный вопрос повторяется. Старое приложение останавливается, восстановленное занимает его прежний порт. MySQL, Weaviate и Ollama восстановленной копии уже работают в отдельной сети. Проверяется healthcheck; при ошибке переключения сценарий пытается вернуть прежнее приложение. Прежние контейнеры и тома не удаляются. Автосинхронизация возвращается к настройке целевого сервера.

На **новом сервере без прежнего развёртывания** используйте `-Fresh -Port 3000`. Это не заменяет настройку домена/HTTPS/Caddy и разрешённых сайтов: архив переносит данные и runtime, но не ОС и reverse proxy. При восстановлении на новый сервер подготовьте его `.env` с нужными внешними настройками либо настройте приватную конфигурацию восстановленного deployment; исходный `.env` из архива не требуется.

После переключения активная конфигурация указана в `.knowledge-active.json`. Для дальнейшего управления используйте:

```bash
bash scripts/compose-active.sh ps
bash scripts/compose-active.sh logs --tail=100 app
sudo bash scripts/audit-server.sh
sudo bash scripts/update-server.sh
```

**Обычный `docker compose` без активного файла по-прежнему указывает на старую базовую конфигурацию.** Скрипты обновления и аудита уже учитывают активную восстановленную копию. Не удаляйте `.knowledge-backups/restore-...`: это её рабочая конфигурация и runtime-файлы.

## 4. Вернуться к прежней базе знаний

```powershell
.\scripts\Switch-Knowledge.ps1 `
  -Server user@server `
  -RemoteProject /opt/assist `
  -RestoreDirectory /opt/assist/.knowledge-backups/restore-ВАШ-ID `
  -Rollback
```

Откат переключает трафик на прежние контейнеры и данные; восстановленная база отдельно сохраняется. **Новые изменения после переключения не объединяются автоматически** с прежней базой. Не выполняйте откат без учёта новых загрузок/разметки/диалогов.

## Проверки реализации

Локальные тесты проверяют состав/повреждение архива, безопасные пути, изоляцию томов/порта/секретов, возобновление сервисов при ошибке и критерии контрольного ответа. Синтаксис Python, Bash и PowerShell проверен. Здесь нет работающего Docker Engine и доступа к серверу, поэтому полный цикл с реальными MySQL/Weaviate/Ollama, SCP и переключением портов **ещё не проверен**. Первый прогон нужно выполнить на отдельной копии сервера; до него нельзя считать восстановление эксплуатационно подтверждённым.

Основание для выбранной схемы: [Docker — backup/restore volumes](https://docs.docker.com/engine/storage/volumes/#back-up-restore-or-migrate-data-volumes), [MySQL — mysqldump](https://dev.mysql.com/doc/refman/8.0/en/mysqldump.html). Восстановление использует прежнюю версию Weaviate; [обновление версии](https://docs.weaviate.io/deploy/migration) — отдельная операция.
