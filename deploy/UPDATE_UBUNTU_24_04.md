# Обновление Ubuntu 24.04 и проверка контейнеров

Изменения пока локальные: перед git pull их нужно проверить, закоммитить и опубликовать в используемом репозитории. На сервере выполняйте команды из папки проекта. Не подставляйте выдуманный путь. Запланируйте окно обслуживания: обновление ОС/Docker может перезапустить службы. Сначала сделайте внешний snapshot/backup сервера и данных.

## 1. Сохранить конфигурацию и получить опубликованный код

```bash
cd /ФАКТИЧЕСКИЙ/ПУТЬ/К/ПРОЕКТУ
umask 077
backup_dir="$HOME/assist-config-backups/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$backup_dir"
cp .env docker-compose.yml "$backup_dir/"
git status --short
git pull --ff-only
```

При локальных изменениях или ошибке git pull остановитесь и разберите различия. Не используйте reset --hard для принудительного обновления. Не заменяйте рабочий .env шаблоном. Новые настройки безопасности описаны в SECURITY.md; сохраните рабочие пароли БД и JWT_SECRET.

## 2. Снять исходный аудит

```bash
sudo apt-get update
sudo apt-get install --no-install-recommends ca-certificates curl python3-venv
sudo bash scripts/audit-server.sh
```

Отчёты находятся в .security-reports/<UTC-время>/. Сначала смотрите scan-status.txt: ошибка сканера не означает отсутствие уязвимостей. Не публикуйте отчёты без просмотра: они содержат инвентаризацию сервера. Скрипт не сохраняет переменные окружения контейнеров и пароли.

## 3. Обновить Ubuntu и уже установленный Docker

```bash
sudo apt-get update
sudo apt-get upgrade

# Обновляется существующая семья пакетов, без замены docker.io на docker-ce.
docker_packages=()
for package in docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin docker.io docker-compose-v2 containerd runc; do
  if [ "$(dpkg-query -W -f='${Status}' "$package" 2>/dev/null)" = 'install ok installed' ]; then
    docker_packages+=("$package")
  fi
done
if [ "${#docker_packages[@]}" -gt 0 ]; then
  sudo apt-get install --only-upgrade "${docker_packages[@]}"
fi
sudo systemctl status docker --no-pager
sudo docker version
sudo docker compose ps
if [ -f /var/run/reboot-required ]; then
  cat /var/run/reboot-required
fi
```

Это Bash-команды. Если Docker установлен через snap или вручную, список пакетов не обновит такой Docker: нужна проверка способа установки. Обновления доступны только из настроенных APT-репозиториев; удержанные пакеты требуют отдельного разбора (`apt-mark showhold`). Не меняйте репозитории автоматически.

При запросе перезагрузки выполните `sudo reboot` в окно обслуживания, затем снова подключитесь, перейдите в проект и проверьте `sudo docker compose ps`. Это обновляет ОС и Engine, но не пакеты внутри контейнерных образов.

## 4. Обновление приложения — OCR отключён

Перед сборкой и перед остановкой приложение проверяет совпадение действующих томов uploads/MySQL/Weaviate/Ollama и настроек БД с новой конфигурацией. При различиях обновление останавливается; не обходите проверку сменой имён томов или удалением данных. `DB_SCHEMA_BOOTSTRAP=true` также запрещён для этого сценария: используются штатные миграции.

Перед переключением сохраняются `database.sql`, `uploads.tgz`, `SHA256SUMS` и количество записей в девяти таблицах документов. После запуска повторный подсчёт должен подтвердить отсутствие уменьшения. Счётчики не доказывают неизменность содержимого каждой записи и не заменяют проверку восстановления резервной копии. Дамп рассчитан на InnoDB; при других движках сценарий остановится и вернёт старое приложение до миграций. Не запускайте несколько обновлений одновременно; внешние задания, которые пишут в БД или uploads, нужно приостановить на время копирования. Существующий каталог BACKUP_DIR не перезаписывается.

Сценарий обновляет только app, оставляя контейнеры и образы MySQL/Weaviate/Ollama без переключения. Полной резервной копии Weaviate он не создаёт: перед любыми изменениями самой векторной БД нужен отдельный backup/snapshot. До обновления рекомендуется проверить восстановление MySQL и uploads на изолированной копии сервера. Не восстанавливайте тестовый дамп поверх рабочей базы.

OCR отключён в автоматической и ручной обработке PDF. PaddleOCR и его зависимости больше не устанавливаются в образ; старые TABLE_EXTRACTOR_* из .env игнорируются, включая REQUIRED=true. Чтение текстового слоя и разбор таблиц по координатам сохраняются. Существующие документы и фрагменты базы знаний не изменяются. Базовый python3 оставлен для сборки нативных Node-модулей, без OCR-библиотек.

Для контролируемой попытки сборки и проверки:

```bash
sudo bash scripts/update-server.sh
```

Сценарий собирает кандидат и проверяет серверный JavaScript до остановки приложения; сборка также проверяет TypeScript. Затем он останавливает приложение для резервной копии MySQL/uploads, переключает контейнер, выполняет миграции через entrypoint и проверяет /healthz. OCR для обновления не требуется; системный python3 на сервере используется только для чтения конфигурации Compose. Backup лежит в ../assist-backups/<UTC-время>/; храните внешнюю копию. Возможен простой во время копирования и запуска. Прерванное обновление после начала миграций требует ручного анализа, автоматического отката БД нет.

После успешного запуска проверьте вход администратора, вопрос в виджете и согласие, открытие вложения, известный RAG-запрос и ручную разметку знакомого PDF с текстовым слоем. Сканы требуют предварительного распознавания вне приложения. Затем повторите:

```bash
sudo bash scripts/audit-server.sh
sudo docker compose logs --tail=100 app
```

## 5. MySQL, Weaviate, Ollama

Не выполняйте общее `docker compose pull && docker compose up -d`: это одновременно изменит несколько сред и затруднит диагностику.

- MySQL 8.0 требует отдельной миграции на поддерживаемую LTS с восстановлением тестовой копии и проверкой приложения.
- Weaviate 1.24.0 требует полной резервной копии и последовательных minor-обновлений по официальной инструкции: https://docs.weaviate.io/deploy/migration . Обновление индексов и совместимость поиска проверяются на копии данных.
- Для Ollama выберите конкретный проверенный релиз/digest, проверьте имеющиеся модели и ответы до замены рабочего контейнера.

Не удаляйте volumes, не запускайте глобальное обновление pip и не удаляйте старый образ/backup до проверки новой версии.
