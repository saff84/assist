# Docker, Python/OCR и Ubuntu — 2026-11-06

> Обновление после аудита: по запросу пользователя OCR отключён. Вызовы Python удалены из автоматической и ручной обработки PDF, PaddleOCR больше не устанавливаются в образ. Старые TABLE_EXTRACTOR_* игнорируются. Сценарий обновления проверяет JavaScript без требования OCR; аудит допускает отсутствие Python. Описанный ниже блокер OCR относится к состоянию до отключения. Для удаления пакетов из существующего контейнера потребуется пересборка и замена образа; сервер автоматически не менялся.

## Область проверки

Trivy 0.76.1, актуальная загруженная CVE-база, публичные образы linux/amd64 из docker-compose.yml/Dockerfile. Digest каждого образа записан в docker-registry-snapshot-2026-11-06.json. Это не проверка работающего сервера: доступа к нему нет; локальный Docker Engine недоступен. Установленные на сервере версии Docker, ядра, пакетов Ubuntu и Python пока неизвестны. Пользователь подтвердил Ubuntu 24.04.

Числа — записи о пакетах, а не количество уникальных CVE или доказанных способов атаки. Одна CVE может встречаться в нескольких пакетах/бинарниках. Базовый Node-образ не равен итоговому образу приложения: Dockerfile дополнительно устанавливает системные и Python-пакеты. Отчёты docker-*-audit-2026-11-06.json содержат версии, исправления и статусы поставщиков.

## Приоритеты

1. **Weaviate 1.24.0:** Alpine 3.19.1 помечен сканером как EOSL. Старые Go/grpc, OpenSSL и musl; среди critical — CVE-2024-24790, CVE-2025-68121 и CVE-2026-33186. Требуется резервная копия и миграция с проверкой поиска. Официальная рекомендация — по одной minor-версии, используя последний patch каждой ветки: https://docs.weaviate.io/deploy/migration . Нельзя просто заменить тег на latest с существующим volume.
2. **MySQL 8.0:** critical обнаружены в комплектующих образа (certifi и Go-коде gosu), что само по себе не доказывает удалённую уязвимость SQL-сервера. Ветка 8.0 завершила жизненный цикл в апреле 2026; нужен отдельно проверенный переход на поддерживаемую LTS. Источник: https://www.mysql.com/support/eol-notice.html . Обновление Docker Engine не обновляет MySQL-образ.
3. **Node base:** часть high относится к npm внутри образа и не отражена в аудите зависимостей приложения. Critical CVE-2023-45853 относится к MiniZip; Debian отмечает её на уровне исходного zlib, поэтому применимость к конкретному zlib1g нужно проверять отдельно, не объявлять подтверждённой RCE: https://security-tracker.debian.org/tracker/CVE-2023-45853 .
4. **Ollama:** оба high — CVE-2026-109518 в apt/libapt-pkg6.0t64; сканер указывает исправление 2.8.4ubuntu0.1. Это не две разные уязвимости API Ollama. latest изменяемый: для эксплуатации следует выбрать проверенный релиз и digest.

Конфигурация Dockerfile: процесс работает от root (DS-0002), нет HEALTHCHECK (DS-0026). В JSON есть дубликат для tmp/baseline/Dockerfile — это не второй рабочий сервис. Перевод на непривилегированного пользователя требует проверки прав существующего uploads volume; здесь автоматически не применялся.

## Python/OCR

Текущие requirements не фиксируют версии. Для Python 3.11/Linux разрешён кандидат из 81 пакета; pip-audit 2.10.1 не нашёл известных уязвимостей, пропущенных пакетов нет. Артефакты: python-ocr-candidate-linux311.txt и python-ocr-candidate-audit-2026-11-06.json. Это не lock-файл проверенной рабочей среды и не аудит установленных на сервере пакетов.

**Функциональный блокер:** свежий набор содержит PaddleOCR 3.7.0, а scripts/extract_tables.py импортирует PPStructure из API 2.x. В 3.x он заменён PPStructureV3. Код перехватывает ошибку импорта и возвращает пустой результат, то есть OCR может перестать извлекать таблицы без явной ошибки пользователю. Инструкция миграции: https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/update/upgrade_notes.en.md .

Нельзя вслепую обновить pip или зафиксировать старую ветку без аудита её зависимостей. Нужны точный набор из рабочего контейнера и проверка на знакомых PDF, затем фиксация совместимых версий либо миграция на новый API. Изменение OCR в этом аудите не выполнялось.

## Сервер и обновление

scripts/audit-server.sh собирает точные image ID, сканирует установленные образы, пакеты Ubuntu и установленный Python, не меняя среду приложения. Инструменты аудита устанавливаются изолированно в .security-reports. Высокие CVE не прерывают сбор остальных отчётов; неполные проверки отмечаются отдельно. Возможны дополнительная нагрузка на диск/CPU и обращения к внешним базам.

scripts/update-server.sh собирает кандидат, проверяет pip check и наличие старого OCR API до остановки приложения, сохраняет .env/старый образ, затем делает согласованную копию MySQL и uploads, запускает миграции и проверяет /healthz. Сейчас свежая OCR-сборка ожидаемо не пройдёт проверку: это защита от ухудшения работающего сайта, а не завершённая миграция OCR. Импорт API не заменяет функциональную проверку распознавания.

Сценарий не обновляет MySQL/Weaviate/Ollama, не удаляет volumes и не откатывает БД автоматически. Полный откат после миграций требует согласованного восстановления БД, uploads и старого образа. Репликации и внешние писатели должны учитываться отдельно; резервная копия MySQL предполагает InnoDB. Для БД и векторного хранилища нужен также проверенный внешний backup/snapshot.

Команды: deploy/UPDATE_UBUNTU_24_04.md. Проверены bash -n обоих сценариев и синтаксис Compose. На реальном Ubuntu сценарии ещё не запускались. Предыдущие проверки приложения: TypeScript без ошибок, 292 теста прошли; эти результаты не подтверждают работу новой Docker/OCR-сборки.
