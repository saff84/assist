# Модерация исходящих ответов — 2026-11-10

Добавлен отдельный административный раздел «Модерация ответов», защищённый на уровне меню, страницы и всех tRPC-методов. По умолчанию включён начальный словарь русского мата/прямых оскорблений и нескольких английских выражений. Настраиваются словарь, основы с *, точные исключения и запасной ответ; доступна проверка текущей формы и журнал событий.

## Проверка ответов

Общий gate находится на выходе processRAGQuery после intent pipeline: он покрывает ранние уточнения, готовые ответы, FAQ, поиск по документам и генерацию для website/bitrix24/test. Входящие вопросы не отклоняются по этому словарю. При блокировке вместо ответа возвращается нейтральный текст без источников, attachments, chunks и diagnostics. Отложенная запись обычной RAG-истории сохраняет уже отфильтрованный текст. Убрана печать первых 500 символов исходного ответа в RAG debug-лог.

Поддержаны распространённые русские словоформы, явные неправильные формы, основы, фразы, регистр/ё-е, часть похожих латинских букв и цифр, невидимые/комбинируемые символы, простые маски/разделители и некоторые Markdown/HTML-представления. Проверка ограничена словами; исключения применяются только в своём месте. Пользовательский произвольный regex не допускается.

## Хранение и ресурсы

JSON находятся в uploads/settings и входят в существующие резервные копии uploads. Файлы заменяются атомарно, настройки/скомпилированные правила кэшируются. Очередь сериализует записи журнала внутри процесса. Журнал содержит максимум 100 событий: канал, дату, причину, правила и SHA-256, без текста ответа/вопроса. Старые события скрываются при чтении и удаляются при следующей записи после 30 дней. Ошибка журнала не прерывает выдачу безопасного ответа; повреждённые настройки дают встроенный нейтральный fallback и ошибку в админке.

После оптимизации на текущей Windows/Node 22 машине: 20 повторов чистого технического текста длиной 16 800 символов, прогретые правила, среднее 7,78 мс вместо исходных около 70 мс. Это замер чистого matcher без дискового I/O, генерации и сетевых вызовов; не гарантия задержки на VPS. Дополнительные модели/LLM-запросы, зависимости и службы не добавлены.

## Валидация

- 383 теста в 51 файле прошли; 87 проверок относятся к модерации: словоформы/маски/технические слова, исключения, роли, preview без сохранения/LLM, атомарное хранение/очередь/retention, повреждения настроек/журнала, очистка побочных payload и общий gate ранних ответов трёх каналов.
- TypeScript без ошибок. Vite app, Vite widget и esbuild server собраны успешно.
- Для модерации нет SQL-миграций, документы/embeddings/индексы не переписываются. Настройки вступают в силу для новых ответов после сохранения без перезапуска.
- На работающем сервере и в браузере с реальной БД раздел здесь не запускался. Требуются публикация изменений, пересборка app и проверка администратором на своих примерах.

Фильтр лексический: полного морфологического словаря и семантического анализа нет. Возможны неучтённые формы/обходы и ложные срабатывания на специфических названиях; для этого есть редактируемые основы, исключения и preview. Существующее хранение общей истории чата/intent traces не заменяется политикой нового журнала.
