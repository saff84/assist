# Полная резервная копия базы знаний — 2026-11-09

## Обновление: обычная копия по умолчанию

Добавлен формат 2 с режимами standard/full. Standard сохраняет только SQL, uploads, Weaviate и настройки/метаданные, без images.tar и ollama.tar. В CLI и PowerShell он выбран по умолчанию. Full и прежние полные архивы формата 1 сохранены.

Образы разрешаются только по точному локальному image ID либо скачиваются по immutable registry digest с последующей проверкой ID. Для локального образа приложения без доступного registry требуется сохранить его отдельно или использовать full. Модели из существующего кэша копируются на сервере в новый том с read-only доступом к оригиналу; недостающие скачиваются туда и проверяются по digest. Отличающиеся веса не принимаются, сохранённые embeddings не перестраиваются. В режиме standard Ollama не останавливается для резервного копирования.

После изменения прошли 32 теста backup/restore и 10 тестов защиты хранилищ. Отдельный тест собирает обычный архив через реальную функцию backup с имитацией Docker: подтверждает отсутствие моделей/образов и отсутствие остановки Ollama. Остальные новые проверки покрывают обратную совместимость, reuse/download по digest и запрет незаметной замены модели. Описание первоначального полного механизма ниже относится к режиму full.

Реализованы серверный CLI scripts/knowledge_backup.py и PowerShell-сценарии Backup-Knowledge, Restore-Knowledge, Switch-Knowledge. Инструкция: deploy/KNOWLEDGE_BACKUP.md.

Архив включает все таблицы БД приложения, uploads, холодный том Weaviate, полный том моделей Ollama, точные образы четырёх сервисов, RAG-конфигурацию/промпт, параметры моделей, инвентаризацию и SHA-256. Исходный .env не экспортируется. Поддержана текущая одноузловая локальная Docker Compose-схема; источник БД/векторов/моделей проверяется, нестандартное расположение/удалённый источник не выдаётся за полную локальную копию.

Восстановление импортирует данные в новые уникальные тома и отдельную сеть, без подключения к действующим томам. До переключения проверяются SQL-счётчики, число записей документов после запуска/миграций, хеши каждого исходного файла, количество объектов Weaviate, точные модели и размерность embeddings. Контрольный вопрос должен вернуть ожидаемый фрагмент ответа и источники документов. При включённом согласии проверяется и этот путь API.

Переключение и откат — отдельные команды. Прежние тома/контейнеры сохраняются. При неудачном переключении выполняется попытка возобновления старого приложения. После переключения helpers обновления/аудита учитывают .knowledge-active.json. Для ручного Compose добавлен compose-active.sh. Операции backup/restore/promote/rollback и update используют общий lock.

- 10 тестов защиты действующих хранилищ и инвентаризации.
- 294 теста приложения и TypeScript без ошибок.
- Синтаксис Python, PowerShell и Bash; сгенерированный Compose проверен Docker Compose config без Engine.
- Русскоязычный вопрос с кавычками и shell-символами проверен на сохранность в JSON/base64 payload SSH с имитацией клиента. Данные не вставляются в исполняемый shell-код.

## Не выполнено здесь

Реального Docker Engine нет (docker version сообщает об отсутствии pipe docker_engine), доступа SSH к серверу нет. Полный цикл с MySQL import, холодным восстановлением Weaviate, загрузкой моделей, HTTP RAG, SCP и реальным переключением портов не запускался. Имитационные тесты не заменяют этот прогон. Первый цикл должен пройти на отдельной копии сервера до использования механизма на production. Серверные данные не менялись; изменения локальные и ещё не опубликованы.

Архив не зашифрован и предназначен только для доверенного защищённого хранения. Это не перенос ОС/HTTPS/reverse proxy. Секреты интеграций и доменные настройки целевого сервера должны быть корректно настроены. Один контрольный вопрос не доказывает корректность всех возможных ответов. Не удаляйте старые данные и проверочную конфигурацию после первого успешного запроса.
